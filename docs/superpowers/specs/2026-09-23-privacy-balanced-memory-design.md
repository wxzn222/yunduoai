# AI 云朵记忆模块修订需求（隐私与体验平衡版）

## 1. 目标与原则

AI 云朵需要让用户感到对话具有连续性，但不应将全部聊天内容转为永久档案。本方案采用“最小必要记忆”原则：仅保留对后续陪伴确有长期价值的低敏感信息；敏感信息和一次性情绪事件默认不进入长期记忆。

目标：

- 在相关场景下自然使用记忆，避免机械复述或无关提起。
- 不要求用户登录、姓名、手机号或其他真实身份信息。
- 用户可查看、编辑、删除和一键清除自己的记忆与聊天数据。
- 过期信息自动淡出，避免错误记忆长期影响回复。

## 2. 记忆分层

### 2.1 短期上下文

- 范围：当前会话最近 8 个用户回合及对应回复；该数值可配置。
- 用途：维持本次聊天的语义连贯。
- 保存：完整消息仍按聊天记录规则保存，但不因短期上下文自动成为长期记忆。

### 2.2 长期陪伴记忆

仅保存下列低敏感、具有持续价值的信息：

- 兴趣爱好：例如喜欢画画、看展。
- 长期计划或进行中事项：例如正在准备考研；需带有效期或复查时间。
- 沟通偏好：例如希望少建议、多倾听。
- 使用偏好：例如对云朵的称呼、偏好的交流节奏。
- 稳定的非敏感生活习惯：例如常在深夜使用；仅当用户明确且重复表达时记录。

长期记忆只在与当前话题相关时作为回复上下文使用。系统不得宣称知道用户未提供的信息，也不得每次开场主动复述记忆。

### 2.3 敏感信息隔离

以下内容不得写入长期陪伴记忆：

- 真实姓名、学校、住址、联系方式、证件、账号、密码等身份或财产信息。
- 自伤、自杀、伤人风险及其具体细节。
- 健康、诊断、治疗、创伤、性侵、家庭暴力等高度敏感内容。
- 单次争吵、当日心情、随口表达等一次性且无长期价值的信息。

危机信息仅进入独立的安全处置流程，不得作为未来聊天时主动提起的记忆。

## 3. 记忆生成与触发

### 3.1 触发条件

系统不以“10 分钟无消息”作为唯一会话结束依据。满足以下任一条件时，可异步进行候选记忆提取：

1. 用户主动点击“结束聊天”或“保存这段记忆”。
2. 用户 30 分钟无新消息，且当前会话至少包含 3 个用户回合。

触发只表示“允许评估”，不表示一定保存记忆。

### 3.2 提取规则

- 优先使用规则白名单和敏感词过滤；通过后才允许模型生成候选记忆。
- 模型只输出结构化候选记忆，不输出用户对话原文。
- 每条候选必须标明类别、置信度、来源会话、创建时间和过期时间。
- 没有符合条件的信息时，输出空数组，不创建记忆。
- 每位匿名用户每天最多执行 3 次候选提取。

### 3.3 自动激活与人工复核

- 高置信度、白名单类别、无敏感风险的候选，自动成为 \`active\` 记忆。
- 表述模糊、可能过期或价值不明确的候选，保存为 \`review\`，不主动用于回复。
- 用户在记忆页面可将 \`review\` 设为启用、编辑或删除。

## 4. 数据结构

每条长期记忆建议采用独立表，字段如下：

| 字段 | 说明 |
| --- | --- |
| memory_id | UUID，记忆唯一标识 |
| user_id | 匿名用户 UUID，不保存真实身份 |
| category | interest / goal / communication_preference / usage_preference / routine |
| content | 经规范化后的短文本，不保存整段原始对话 |
| confidence | 0 到 1 的提取置信度 |
| status | active / review / deleted |
| source_chat_id | 来源会话，支持用户删除来源数据时追溯处理 |
| created_at | 创建时间 |
| last_confirmed_at | 最近被用户确认或再次提及的时间 |
| expires_at | 到期时间；长期稳定偏好可为空 |
| mention_count | 被用户明确提及或确认的次数 |

相同类别和相同规范化内容应合并：更新 \`mention_count\`、\`last_confirmed_at\`，而非重复创建。内容冲突时保留新旧记录，但只允许较新且 \`active\` 的记录进入提示词。

## 5. 使用与遗忘规则

- 每次回复最多带入 3 到 5 条最相关记忆，总长度不超过 300 个中文字符。
- 仅在当前消息与记忆类别相关时带入，不相关时不传给模型。
- 计划类记忆默认 90 天到期；用户再次提及则延期。
- 普通兴趣和偏好 180 天未被提及或确认时转为 \`review\`；再过 90 天自动删除。
- 用户明确删除的记忆立即标为 \`deleted\`，不再进入任何提示词。
- 用户删除某个会话时，系统应提示是否同时删除该会话生成的记忆。
- 用户选择“清除我的全部数据”时，删除匿名账户关联的聊天记录、长期记忆、危机事件和会话元数据；法律或安全合规要求必须保留的数据需在隐私政策中单独说明。

## 6. 用户告知与控制

首次进入时，以简洁弹窗或隐私说明告知：

> 为了让后续聊天更连贯，云朵可能记住你主动分享的兴趣、计划和聊天偏好。它不会把联系方式、住址、健康与危机内容写入长期记忆。你可以随时在“我的记忆与数据”中查看、修改或清除。

提供“我的记忆与数据”入口，支持：

- 查看当前 \`active\` 和记忆待复核项。
- 编辑或删除单条记忆。
- 一键关闭长期记忆功能；关闭后不再提取或使用长期记忆。
- 一键删除全部聊天记录与匿名数据。

匿名身份通过浏览器 Cookie 关联随机 UUID。用户更换设备、使用无痕模式或清除 Cookie 后将被识别为新匿名用户，不能自动找回旧数据；该限制必须在隐私说明中明确。

## 7. 验收标准

- [ ] 只从白名单类别提取候选记忆；敏感信息、危机信息和一次性情绪事件均不进入长期记忆。
- [ ] 未达到触发条件的会话不执行记忆提取；每天每位用户最多提取 3 次。
- [ ] 高置信度低敏感记忆可自动启用；不确定记忆不主动用于回复。
- [ ] 新对话仅带入相关且未过期的 \`active\` 记忆，长度不超过 300 个中文字符。
- [ ] 用户可查看、编辑、删除单条记忆，关闭长期记忆，并一键清除全部匿名数据。
- [ ] 用户删除记忆或全部数据后，该信息不再被后续回复使用。
- [ ] 计划类、普通偏好类记忆按规则到期、降级或删除。
- [ ] 用户首次使用时可获得清晰的数据与记忆告知。

## 8. 与原验收文档的主要变化

| 原方案 | 修订方案 |
| --- | --- |
| 10 分钟无消息即判定会话结束 | 30 分钟无消息且至少 3 回合，或由用户主动结束；仅触发评估，不保证保存 |
| 全部候选记忆先 \`pending\` | 高置信度低敏感信息自动 \`active\`；不确定信息才进入 \`review\` |
| 三元组可保存较广泛用户事实 | 使用严格白名单分类和敏感隔离，避免形成用户画像档案 |
| 记忆长期保留 | 设到期、降级和自动删除规则 |
| 重点是后台管理员确认 | 重点是用户本人查看、修改、关闭和清除 |

## 9. 非目标

- 不实现跨设备身份找回；如需该能力，应由用户自愿注册或绑定账号。
- 不将记忆用作广告、画像推荐或向第三方共享。
- 不以长期记忆替代危机干预、心理诊断或专业服务。
